# 交易日记

交易日记只读展示本地服务已记录的虚拟成交；展开、加载更多和查看日记不会发出交易请求。它不是券商流水，也不是完整历史或投资建议。

## 页面与静态资源

`pet.html` 在 `pet.css` 后加载 `pet-diary.css`，以沿用现有粉色、浅色边框和控件样式。`pet-diary.js` 与 `pet-ui.js` 都使用 `defer`，前者必须在后者之前；`pet-ui.js` 将服务返回的 `state.tradeDiary` 交给 `window.PetDiary.render`。页面预置 `diary-notice`，提示本地存档、保留范围及不完整历史。

日记样式仅作用于 `.activity`、`#diary-notice` 和 `#activity-log`，不改桌宠、气泡、GIF 或表情包区域。每笔成交使用原生 `details/summary`，明细为 `dl/dt/dd`。盈利为红色、亏损为绿色，同时保留正负号和文字，不仅靠颜色区分。未结算和未知口径用中性色。长品种标识、数值和说明允许换行；明细列使用 `minmax(0, …)`，不设固定宽度以适配 390px 窄屏。此轮只做静态约束与 Node 测试，未运行浏览器视觉验证。

服务的静态白名单与分发/打包资源清单必须同时包含 `pet-diary.js` 和 `pet-diary.css`；仅添加 HTML 引用并不保证资源能被访问。

## 数据来源、持久化和边界

- 服务 `GET /api/state` 返回独立的 `tradeDiary`；分钟、小时、日图表切换不改变这份日记。浏览器不使用 `localStorage` 保存成交。
- 日记保存在服务快照的 `candleHistory.trades`，默认与账户、收益历史一起写入 `~/.kurumi/live-state.json`。`createService({ statePath })` 可指定独立路径，`statePath: null` 关闭持久化。脏状态通常至少间隔 30 秒落盘，正常停止时强制保存；异常退出前尚未落盘的成交可能丢失。服务通过同目录临时文件与重命名进行原子替换。
- 最多保留最近 **500 笔**有效成交，包含开多、平多、开空、平空及强平成交；不是只保留 500 笔已结算交易。归档接收顺序保存，页面按成交时间倒序展示，首次显示 12 笔，按需每次增加 12 笔。局数用于区分轮次，不因破产开启新一轮而主动清空已有成交。
- 服务使用事件序号游标避免重新消费旧事件，同时对当前保留集按成交 ID 去重；保留集以外的任意历史 ID 并非永久去重索引。页面也按 ID 去重，不修改服务数据。
- 超出 500 笔时移除最早归档项并置 `truncated: true`。`startedAt` 记录归档首笔起点，截断后不重置；`oldestRetainedAt` 表示目前最早保留项，两者含义不同。旧格式仅能从可保留的旧项推断起点与截断，不能还原已丢失记录。
- `partialHistory` 明确为真：迁移前、服务未记录期间、损坏存档拒绝恢复后或事件保留窗口之外的成交不保证完整，不能把没有记录解释为没有交易。没有起点时显示“尚无记录起点”。
- K 线历史有约 1 MiB 预算，整个服务快照有 2 MiB 预算。字节预算先裁剪行情/权益条目，不凭空补齐数据，也不偷偷把日记改成完整历史；500 笔日记的截断标记与图表截断标记独立。快照仍超限时操作会被拒绝。

## 收益口径与未知字段

开仓项显示“未结算”，不把资金流、成交额或保证金当成已实现盈利。平仓的 `pnlBasis: net-position-interest` 才标作“净收益”：已知价差收益 `grossPnl` 减去分摊到此次平仓的已知仓位利息 `interest`。部分平仓按仓位比例分摊利息；多头价差是卖出额减成本，空头价差是成本减买回额。强平亦保留可得的仓位利息、融资偿还、释放保证金和穿仓差额，不能仅凭退回现金推断收益。

“净收益”不是账户全成本利润：**个人贷款利息未分摊到单笔成交**，不包含未平仓浮动盈亏，也不应据此与账户收益直接逐笔相加对账。

旧记录缺少 `pnlBasis` 时归为 `unknown`。若仍有有限的 `realizedPnl`，展示“旧口径收益”，不宣称已扣除利息；若没有可靠收益数值，展示“收益依据不足”。缺失成交额、成本、利息等字段不按现价倒推、不补零；真实数值 0 仍展示。未知旧多头利息不会由前端伪造成净收益。

## 验证与安全

执行：`node --test tests/pet-diary.test.cjs tests/pet-diary-integration.test.cjs`。

现有单元测试覆盖收益口径、去重与保留数量、安全文本输出、分页、展开状态及空状态。集成测试覆盖页面静态链接与延迟脚本先后、浏览器 UMD 模块契约、真实服务资源响应，以及服务保存/重启后 `tradeDiary` 保持一致和旧口径标识不被升级。

集成测试只使用临时目录中的合成账户快照、固定时钟、空采样提供者、自己创建的随机本地端口和 GET 请求；不连接既有服务、不读写真实账户存档，不调用下单、借贷或重置接口，不运行应用构建或浏览器。测试结束停止自建服务，并校验临时路径后清理。
