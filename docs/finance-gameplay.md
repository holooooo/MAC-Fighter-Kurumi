# 虚拟金融玩法：授信、计息、收益与多局清算

> 这是本地桌宠游戏规则，不是现实投资、信贷、会计或法律服务。韭币不可充值、兑换、提现；本产品不连接券商，不建立真实债权，也不影响现实信用记录。「个人破产」仅为游戏清算按钮，不等于法律上的破产申请或债务免除。

本文核对[引擎](../pet-engine.js)、[采集服务](../server.cjs)及[收益历史模块](../performance-history.cjs)。页面展示与按钮说明应服从这些规则，不把角色玩笑当金融建议。

## 1. 真实的是采样，虚拟的是交易

CPU、内存、负载和明确接入的外设／Agent 指标来自实际采集；它们被映射为游戏品种价格，不是可购买的证券或资产。未接入、权限不足、过期和读取失败均需明示，不能填随机值或零值冒充实时数据。真实采到 0 与没有数据不同；0 价格不能被用来无限买入。

现金、持仓、杠杆、利息和净权益全部为虚拟账本。用户可在游戏里看到大额亏损或负净权益，这不表示现实欠款，更不应触发真实支付或催收。角色不因玩家离开或游戏亏损死亡，不能用家庭悲剧催促回本。

## 2. 虚拟无限授信

服务启用 `credit.unlimited=true`，每笔个人借款最少 100,000、最多 3,000,000 虚拟韭币，两个边界均包含。这里「无限」只表示没有另设固定的累计玩法额度，不表示单笔无限、数值无限或可向现实机构无限借款。

每次借款同时增加现金和个人贷款本金。例如借入 100,000 时，现金增加 100,000，债务也增加 100,000，净权益和当下盈亏不因此增加。还款相反：现金与债务同步减少，不把还款记成投资亏损。欠款可能同时包含个人贷款和仓位杠杆融资，账户总债务必须包括两者。

引擎的金额安全检查要求有限数且绝对值不超过 `Number.MAX_SAFE_INTEGER`（9,007,199,254,740,991）；现金、总债务、交易名义价值、利息及单次清算记录仍须在安全范围内，不能写入 Infinity、NaN 或静默绕回。跨局累计审计总额是例外：累计豁免债务或结晶亏损超过边界时饱和到该上限，并标 `totalsCapped:true`，不因此阻止本次清账或后续合法借款。界面需以「≥／已到数值安全边界」标识这些总额，最近 20 条单次记录仍保留实际安全范围内的数值。该上限不是无限精度或银行级定点精度承诺；不得将大数输入当作加速生成收益历史的通道。

独立引擎未启用无限授信时仍可保留其 `loanLimit` 规则；不要用这种兼容模式解释当前桌宠服务的授信行为。

## 3. 自主投资与自动借款

当前服务新开局默认启用 momentum 自主投资和 `autoBorrow`，旧存档的用户暂停选择应保留。用户必须能在界面看见并关闭自动投资／自动借款。关闭策略不自动平仓、不清除债务，也不停止仍在运行的服务计息。

自动借款不是定时撒钱。引擎需先找到有有效新鲜报价、足够已收盘历史的策略候选；可用现金扣除保留额后不超过 1，且开启 autoBorrow 和无限授信时才考虑借款。风险偏好低于 0.35 不借；两次自动借款至少间隔 60 秒；预算比例为 0 不借。借款金额随风险偏好映射在 100,000–3,000,000 区间。策略买入使用 1 倍现款执行，即使现金来自虚拟个人贷款，也不能将其描述为「没有债务风险」。

momentum、dip、dca 的候选评分和 hold 原因应展示为当前游戏规则，不是未来收益预测。没有历史或现金条件不满足时保持等待，不为凑交易次数借款。不要承诺点一下就产生几千亿收益或债务；累计额取决于真实经过时间、用户操作、采样、利息和实际账本结果。

## 4. 计息与停机

当前默认 `loanRate=0.00002`，它是每个 `market.tickMs` 基准周期的游戏利率，不是年利率。默认周期为 1,000 ms；live 模式按上一次已处理时间与本次时间的真实差值换算周期数，并计算：

`新债务 = 旧债务 × (1 + loanRate) ^ (实际经过毫秒 / tickMs)`

个人贷款与仓位融资均计息。相同／倒退时间戳不重复计息；一次延迟不按额外 UI 点击次数收费。该复利设置为游戏机制，不能换包装成现实融资报价或宣传「低息」。

服务持续运行时，隐藏桌宠、关主窗口、暂停自主投资都不暂停债务计息。服务停止再启动时重建 live 计时基线，不补算停机的离线利息，也不补造离线行情。进程休眠、暂停或调度阻塞而未重新启动时，下一次 live tick 可能按实际时间差计息；这与完整停止服务后的恢复不同。资产价格没有新样本时，估值可能 stale，不能将陈旧价格显示为刚发生的成交或市价。

利息使净权益下降。现有高杠杆仓位还可能触发游戏强平。强平是仓位风险处理，虚拟个人破产是用户主动清空整局账本，两者不是同一动作。

## 5. 净权益、盈亏与收益率

- 持仓市值 = 各持仓数量 × 各自最近可用游戏价格后求和。
- 总债务 = 个人贷款余额 + 各仓位融资余额（含已计入利息）。
- 净权益 = 现金 + 持仓市值 − 总债务。
- 本局盈亏 `pnl` = 净权益 − 本局 `initialCash`。
- 收益率 `returnPct` = pnl / initialCash × 100；基线为 0 时为 `null`，应显示「不可计算／—」，不是 0% 或无穷大。

这里的 returnPct 已使用百分比单位，5 表示 +5%，UI 不应再乘一次 100。买入造成的点差、卖出所得、融资利息都通过账本影响净权益；单个仓位的价差或单笔 realizedPnl 不是整个账户收益的替代。

在允许负净权益的场景，收益率可低于 -100%。界面必须保留负号和真实金额，不截到 0、不压成 -100%，可用万／亿单位提高可读性但需保留查看准确值的方式。接近安全边界时拒绝进一步操作并清楚提示，不应继续绘图假装成功。最终账本不以「角色开心」或「本金变大」代替数值证明。

## 6. 10 秒实测收益历史

盘口 K 线与收益曲线都有时间桶，但不是同一套数据：盘口保存实际指标 OHLC；收益模块保存真实观察到的账户净权益。收益历史的桶宽为 10,000 ms，同桶以最新观察替换最后一点，时间戳保留实际观察时刻，最多 720 点。没有观察的桶保持缺口，不插值、不预填开局资本点、不从种子生成过去走势。

每个收益点含 `time/equity/pnl/returnPct/stale`。持有品种报价过期时，应标估值 stale；恢复旧快照不将旧记录改写成新采样。10 秒桶不保证每 10 秒一定有一个点；断线或停机后曲线自然有空白。零基线的新局仍可画净权益／盈亏金额，但不能构造百分比收益。

主面板采用本地 MIT Chart.js + chartjs-chart-financial，另带 Luxon 与时间适配器；[依赖清单](../vendor/chart-dependencies.json)记录原发行文件、版本、许可和哈希。运行时不依赖 CDN。当前不使用 TradingView／Lightweight Charts，不通过删署名或遮品牌宣称合规。

## 7. 一键「虚拟个人破产」的精确效果

这是不可逆的当前局清算，界面需要显式确认，而不是普通开平仓按钮的别名。执行前记录旧账户最后一次实际估值，随后：

- `cash=0`、`positions={}`、`loanBalance=0`，连同仓位一并清除其融资债务。
- `initialCash=0`，不补发起始现金；自动投资 `enabled=false`，不会清完立即继续借款。
- 行情、品种和真实历史不改；人格与 autoBorrow 设置不自动重写。用户将来主动恢复策略前应看到这些设置。
- 保留累计清算账本并产生 bankruptcy 事件；收益曲线进入新 episode，不连一条向上的线把债务豁免当交易利润。

该操作即使在正净权益时也会清掉现金和持仓，因此必须说明「清空当前资产与债务」，不能只写「免债」。破产后若仍想继续，需要显式借款或恢复允许的玩法；不会因为盈亏归零就认定上一局已回本。

## 8. 多局历史与豁免不是盈利

`bankruptcyLedger` 保存：

| 字段 | 含义 |
| --- | --- |
| count | 累计虚拟破产次数 |
| totalForgivenDebt | 累计游戏清除的债务，绝不是盈利 |
| totalCrystallizedLoss | 各局 `max(0,-pnl)` 的累计结晶亏损 |
| records | 最近最多 20 条清算记录，不是全部永久明细 |

单条记录有 `time/equity/pnl/debt/cash/assetValue/crystallizedLoss/forgivenDebt`，保留清算前账本状态。累计亏损是所有清算局负盈亏的和，不与其他局盈利净额抵销；不要把它误称跨局净收益。

收益 `episode` 从 1 开始，清算后递增。`lastRun` 保存刚结束的上一局摘要及最后最多 120 个实测点，当前局 points 重新开始。系统不保存每一局完整无界曲线：更早的清算通过累计账本与最近记录解释。新局 baseline/equity/pnl 都为 0、returnPct 为 null；这是真实游戏清算结果，不是补造过去的一段平滑回本曲线。

例如上一局净权益 -80,000、初始资金 10,000，则结晶亏损为 90,000。清算后当前局显示净权益 0，不应画成赚回 80,000；上一局 -90,000 盈亏与被清掉的债务分别留在对应历史里。这个算式仅说明口径，不是预填给用户的交易记录。

## 9. 产品验收边界

借款和还款不能凭空增加净权益；自动预算为零不借款；缺少有效采样不下自动单；同一时刻不重复计息；服务重启不制造离线历史。破产必须保留旧局亏损、暂停策略并启新 episode，零基线收益率不得除零。历史和 ledger 有界，非法大数拒绝而不是损坏存档。

本文描述实现契约，不宣称所有设备已完成 UI／长期数值稳定性验收。用户看到的是当前真实采样驱动的虚拟账本，不是可兑现财富、现实债务、法律意见或投资建议。
